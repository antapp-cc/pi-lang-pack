# 更新与发布

这份文档说明**在线更新是怎么工作的**、**发新版要改哪里**、**发完怎么验证**。
之前这些信息只在 `README.md` 里占 7 行、没有发版步骤，是漏掉的。

## 1. 两个实现，一份清单

| | C# 版 | AutoIt3 版 |
|---|---|---|
| 源码 | `src/` | `au3/` |
| 产物 | `PiLang.exe`（51.8MB，免运行时自包含） | `PiLang-AU3.exe`（1.4MB，免运行时） |
| 版本号定义 | `src/PiLang.csproj` 的 `<Version>` / `<AssemblyVersion>` | `au3/lib/Updater.au3` 的 `$UPD_APP_VERSION` + `au3/build/build.ps1` 的版本资源 |
| 发版脚本 | 无（手工 `dotnet publish`） | `au3/build/release.ps1` |
| 配置目录 | `%APPDATA%\PiLang` | 同一个 |

两个版本**共用一份更新清单** `server/latest.json`，也共用同一个版本号。
当前都是 `1.0.11`，所以在更新系统里等价：谁也不会把谁替换掉。

> 两个版本共用托盘互斥名（`Local\pi-lang-pack`），不能同时常驻，后启动的会静默退出。

## 2. 更新机制

客户端启动 15 秒后检查一次，之后每 6 小时一次，托盘「检查更新」也能手动触发。
手动检查会弹进度窗。

### 清单格式

`server/latest.json`：

```json
{
  "lang": {
    "url": "https://raw.githubusercontent.com/antapp-cc/pi-lang-pack/main/server/zh-CN.json",
    "sha256": "词表文件的 SHA256",
    "updatedAt": "2026-11-10T14:13:53.779Z",
    "version": "0.6.4"
  },
  "app": {
    "url": "https://github.com/antapp-cc/pi-lang-pack/releases/download/vX.Y.Z/PiLang-AU3.exe",
    "sha256": "exe 文件的 SHA256",
    "updatedAt": "2026-11-10T14:13:53.779Z",
    "version": "X.Y.Z"
  }
}
```

### 判定规则

- **程序**：`app.version` 比本机版本新才下载（只比版本号，**不比内容哈希**）。
- **词表**：本地文件 SHA256 与清单一致 → 跳过；清单 `updatedAt` 比上次应用时间旧 → 跳过（防 CDN 缓存把新词表盖回去）。
- **下载**：只接受 https（`http://localhost` / `127.0.0.1` 例外，本地测试用）；内容必须与清单里的 SHA256 一致，否则重试 3 次后拒绝。
- **更新源**：`updateUrl` 可以用 `;` `,` 换行分隔多个，按顺序串行尝试；GitHub raw 地址会自动追加 jsDelivr 镜像
  （`cdn.jsdelivr.net/gh/owner/repo@ref/path`），国内直连 raw 不通时靠它。
- **程序替换**：下载 → 校验 → 生成 GBK 编码的 `update-runner.cmd` → 退出 → 批处理等进程退出后复制替换并重启，
  旧 exe 保留为 `.exe.old`。

### 版本号必须递增

更新只比版本号。**同版本号重新发内容，老用户拿不到**（判定"不比本机新"）。
每次发版都要 +1，并把新清单推上去。

## 3. 发版步骤

### AU3 版（推荐，一条命令）

```powershell
cd C:\Users\Administrator\Desktop\Pi多语言包-AU3

# 1) 改版本号（两处都要改）
#    lib\Updater.au3   $UPD_APP_VERSION = "1.0.12"
#    build\release.ps1 -Tag v1.0.12 -Version 1.0.12（或直接传参）

# 2) 生成发布物：编译 + 复制 + 算 SHA256 + 写 latest.json
pwsh -NoProfile -File build\release.ps1 -Tag v1.0.12 -Version 1.0.12

# 3) 上传 exe 到 Release
gh release create v1.0.12 "dist\发布\PiLang-AU3.exe" --title "v1.0.12" --notes "更新说明"

# 4) 清单覆盖仓库，提交推送
copy dist\发布\latest.json server\latest.json
git add server/latest.json au3 && git commit -m "v1.0.12" && git push
```

### C# 版（手工）

```powershell
cd C:\Users\Administrator\Desktop\Pi多语言包

# 1) 改版本号：src\PiLang.csproj 的 <Version> 和 <AssemblyVersion>

# 2) 发布自包含单文件
cd src
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o ..\dist\selfcontained

# 3) 上传 + 改清单（sha256 用 Get-FileHash 算，写进 server\latest.json 的 app.sha256）
gh release create v1.0.12 "..\dist\selfcontained\PiLang.exe" --title "v1.0.12"

# 4) 提交推送
cd ..
git add server/latest.json && git commit -m "v1.0.12（C# 版）" && git push
```

> 注意：`app.url` 指向哪个 exe，就等于"以后所有人升级到哪个实现"。
> 现在指向 AU3 版；如果想让 C# 版用户继续待在 C# 版上，就别把清单指向 AU3 版以外的机器无法区分的东西 ——
> 只能指向一个文件，所以**升级方向是单向的**，选好了别来回改。

## 4. 发完怎么验证

```powershell
# 1) 清单是否生效（raw 有 CDN 缓存，加时间戳绕过）
(Invoke-WebRequest "https://raw.githubusercontent.com/antapp-cc/pi-lang-pack/main/server/latest.json?t=$(Get-Date -Format s)").Content

# 2) release 里的文件能不能下、SHA 对不对
$t = "$env:TEMP\check.exe"
Invoke-WebRequest "https://github.com/antapp-cc/pi-lang-pack/releases/download/vX.Y.Z/PiLang-AU3.exe" -OutFile $t
(Get-FileHash $t -Algorithm SHA256).Hash.ToLower()   # 应等于清单里的 app.sha256

# 3) 用发布版自己检查一次（隔离配置，不碰真实用户配置）
$env:PILANG_CONFIG_DIR = "$env:TEMP\pilang-check"
.\dist\Pi多语言包-AU3.exe --update
```

## 5. 已知坑

| 坑 | 现象 | 处理 |
|---|---|---|
| GitHub raw 直连不通 | 检查更新报"网络超时" | 靠 jsDelivr 镜像；或开代理。客户端已自动追加镜像 |
| raw CDN 缓存 | 清单更新了但客户端还拿到旧内容 | 清单里 `updatedAt` 防降级（词表）；验证时 URL 加 `?t=时间戳` |
| 同版本号重发内容 | 老用户永远不更新 | 每次发版 +1 |
| SHA256 写错 | 客户端重试 3 次后拒绝更新 | 发布后按第 4 节第 2 步核对 |
| Release 文件名带中文 | 下载 URL 需要百分号编码，可能失败 | 发布用的 exe 名保持 ASCII（`PiLang-AU3.exe`），程序显示名在版本资源里 |
| 两个版本同时常驻 | 后启动的静默退出 | 只留一个；配置目录是共用的，不会丢状态 |
| 杀软误报 | AutoIt 版更容易被报 | 加信任；行为是"改别的软件的安装目录"，启发式容易命中 |

## 6. 发布检查清单

- [ ] 版本号已 +1（C# 的 csproj 和/或 AU3 的 `$UPD_APP_VERSION`）
- [ ] `--selftest` 全绿
- [ ] 编译产物版本信息正确（右键属性看文件版本）
- [ ] Release 上传成功，文件名是 ASCII
- [ ] `server/latest.json` 的 `sha256` 与实际文件一致
- [ ] raw 清单拉下来确认内容正确（加 `?t=` 绕过缓存）
- [ ] 用发布版 `--update` 跑一次，输出符合预期
